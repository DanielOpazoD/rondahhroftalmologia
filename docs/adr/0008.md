# ADR 0008: La especialidad como módulo con contrato

**Estado:** Aceptada

## Contexto

En el futuro habrá rondas de otras especialidades. El código de oftalmología no debía quedar mezclado con la plataforma.

## Decisión

- Todo lo clínico (catálogos, validación, formulario, PDF, nota, Excel, seudonimización, casos de ejemplo) vive en `src/specialties/<id>/`.
- La plataforma la usa solo a través de `src/specialties/activa/`. ESLint lo obliga, y `contrato.js` valida el módulo antes de cada build.

## Consecuencias

- Agregar una especialidad es crear un módulo y construir con `ESPECIALIDAD=<id>`.
- Las salidas (PDF, Excel, nota) quedan congeladas con pruebas de referencia.

## Alternativas descartadas

- **Especialidad configurable desde la interfaz:** demasiada complejidad para la necesidad actual.
