# ADR 0005: Ids opacos en el servidor para ids derivados de datos personales

**Estado:** Aceptada

## Contexto

Las fichas de pacientes y los perfiles usan ids deterministas, derivados del RUT, para que dos PC no creen duplicados. Pero hay pocos RUT posibles: una huella sin clave se podría revertir probándolos todos (hallazgo de una revisión de seguridad automática).

## Decisión

- En los espacios con estos ids, el servidor ve `h_` + HMAC (subclave del equipo) del id local.
- El id local viaja solo dentro del contenido cifrado (`lid`), y cada PC verifica que corresponda al id opaco.
- Los ids en claro de versiones anteriores se migran solos (se bajan, se re-suben opacos y luego se borran con `purge`, que solo acepta esa forma de id).

## Consecuencias

- El servidor no puede asociar elementos a un RUT.
- Las atenciones conservan su id aleatorio (no hacía falta cambiarlo).

## Alternativas descartadas

- **Ids aleatorios para las fichas:** dos PC sin conexión crearían duplicados del mismo paciente.
