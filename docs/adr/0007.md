# ADR 0007: El paciente como unidad e identidad por RUT

**Estado:** Aceptada

## Contexto

Un paciente vuelve en distintos operativos y podría atenderse en varias especialidades. Las atenciones sueltas no permitían ver su historial ni evitar duplicados.

## Decisión

- Hay una **ficha de paciente** (datos demográficos) en un espacio común a las especialidades, y cada atención es un episodio vinculado por `pacienteId`.
- La identidad se **resuelve por RUT** entre las fichas existentes (`resolvePatientId`); el id solo es una llave estable.
- Los duplicados se detectan (mismo RUT, o mismo nombre sin datos que los distingan) y se **unen** con una marca `fusionado_en`, que se sincroniza. Los ciclos se resuelven de forma determinista: queda vigente el id menor.

## Consecuencias

- El historial queda ordenado por paciente durante años.
- Las fichas no se borran; las atenciones de una ficha unida se re-vinculan solas.

## Alternativas descartadas

- **Ficha maestra centralizada:** requiere servidor con datos en claro.
